# X1 舞蹈 policy 输入精度改进与 154 维模型验证计划

记录日期：2026-10-22。本文记录方案、已知限制和后续验收方式；下文拟议改进尚未实施，不构成精度或真机通过结论。

## 当前进展与并行路线

- 当前部署基线：v11，160 维单帧 actor、29 维 action；身体位置和线速度由内置 IMU/双腿本体估计器提供。
- 现场反馈：多次演示表现不一致；一次约两秒后站不稳，由人手动停止，另一次跳到场地边缘，由人手动停止。当前证据尚不能确认估计误差是原因。
- 已增加 `dance_diag_*.csv`，记录实际 policy 输入、估计状态和命令，详见[舞蹈诊断日志](DANCE_DIAGNOSTICS.zh_CN.md)。尚无新增诊断数据支持的真机估计精度结论。
- 用户正在并行训练 **154 维观测模型**。训练尚在进行，本文未核验该次训练的启动参数、最终 checkpoint、归一化器或效果。

两条路线并行推进：一条提高 160 维模型所需状态的估计精度；另一条训练去掉部分估计输入的 154 维模型，评估真机适应性。154 维模型的效果不能直接证明现有估计器准确，也不能单独证明此前失稳由估计导致。

## 160 / 154 维输入契约

本地训练源码的 `X1FlatWoStateEstimationEnvCfg` 在 `X1FlatEnvCfg` 基础上，仅将 actor 的 `motion_anchor_pos_b` 与 `base_lin_vel` 设为 `None`。对应注册任务是 `Tracking-Flat-X1-Wo-State-Estimation-v0`。以下表格依据这份源码；正在运行的训练仍需用其实际配置快照确认。

索引均从 0 开始，包含两端：

| 输入 | 维数 | 当前 160 维索引 | 154 维预期索引 | 含义 / 来源 |
| --- | --- | --- | --- | --- |
| 参考关节位置 | 29 | 0–28 | 0–28 | 参考动作 q |
| 参考关节速度 | 29 | 29–57 | 29–57 | 参考动作 qd |
| `motion_anchor_pos_b` | 3 | 58–60 | 去掉 | 参考锚点减实际锚点，在实际锚点坐标系表达 |
| `motion_anchor_ori_b` | 6 | 61–66 | 58–63 | 实际锚点到参考锚点的相对旋转，前两列按行展开 |
| `base_lin_vel` | 3 | 67–69 | 去掉 | `base_link` 原点的线速度，在 body 坐标系表达 |
| `base_ang_vel` | 3 | 70–72 | 64–66 | IMU body 角速度 |
| 关节位置减默认角 | 29 | 73–101 | 67–95 | 模型坐标编码器反馈 |

| 上一帧 action | 29 | 131–159 | 125–153 | 首帧清零，之后使用上一帧策略输出 |
| 合计 | | **160** | **154** | `160 - 3 - 3 = 154` |

相对旋转的 6 个量顺序为 `[R00, R01, R10, R11, R20, R21]`。锚点是训练定义的 `lumbar_pitch_link`，由机身姿态和腰部三轴关节计算。

154 维 actor 不直接消费身体位置和线速度，但仍依赖准确的 IMU 姿态、角速度、腰部编码器、关节反馈及时间对齐。本地源码只删 actor 的两个观测项，critic 仍可使用仿真特权状态，这是非对称 actor/critic 的训练方式。

当前 C++ 控制器、导出器、仿真读取器和诊断观测列均固定为 160 维；就绪检查及 Snapshot 路径还依赖完整身体状态。因此，154 维训练完成后需要适配部署，不能直接替换资产，也不能只删数组元素、清零六维输入或跳过现有反馈检查。新模型不再直接看到平移误差和线速度后，对滑移及路线偏差的纠正能力需要独立评估。

## 需要提高精度的基础状态

对现有 160 维模型，重点是 `base_link` 的位置 p、线速度 v、姿态 R，再用同一时刻的腰部编码器做 FK，得到锚点位姿。估计/派生状态影响锚点位置 3 维、相对旋转 6 维和线速度 3 维；这 12 维并非彼此独立估计。

准确性同时包含偏置、随机误差、累计漂移、延迟和多次初始化的一致性。当前滤波协方差来自模型假设，不能当作实测误差；动态输入的标准差也包含真实运动。参考舞蹈描述期望运动，不能用作实际机器人状态真值。

例如：倾角误差 1° 时，重力在水平方向的错误投影约为 `9.81 × sin(1°) = 0.17 m/s²`。若完全没有观测纠正，积分两秒的位置误差约为 0.34 m。现有接触约束会抑制误差，这个例子说明姿态、加速度和接触必须一起检查，并非现场误差的测量结果。

播放开始时已做一次平移和 yaw 对齐，任意初始水平原点通常会抵消；真正需要关注的是对齐之后的漂移、姿态误差和速度偏置。

## 优先级一：标定与真实时间同步

| 核实项 | 当前实现 / 待确认点 | 拟议工作与验证 |
| --- | --- | --- |
| 采样时间和新鲜度 | 驱动按 `gettimeofday` 的发布时刻盖章；SDK 的 `DcuImu` 没有采样时间或序号，缓存读数可能重复 | 优先取得硬件采样时间/序号；若硬件不提供，至少取得接收时间和新包标记，测量延迟与抖动；重复缓存不能续新鲜度。相同数值也不能单独证明缓存冻结 |
| 同源时钟和数据对齐 | 估计器已有按消息时间插值配对，但发布时间对齐不能证明物理采样同步；policy 的最新关节/gyro 与身体状态也可能存在时间差 | 统一时基，测量实际 IMU/关节/身体状态年龄及时间差；根据延迟选择共同采样时刻或受控预测，并验证误差 |
| IMU 单位、轴向、外参 | 要求 body→world 四元数、rad/s 角速度和 m/s² 比力；平移默认 `[0,0,0]`，旋转假设已对齐 base | 核实各轴正方向、静止重力和已知转动；实测 IMU 相对 base 的位置与旋转，正确处理杆臂加速度 |
| IMU 姿态和偏置 | 姿态直接采用上游 IMU 输出；当前初始化窗口为 0.5 秒 | 测量预热前后静止偏置和姿态漂移；偏置需在确认静止承重时标定，不能把真实运动平均成偏置 |
| 关节与力矩 | FK 和载荷判断依赖模型坐标关节位置、速度、力矩 | 核对零位、方向、尺寸、足底接触几何，以及力矩反馈的符号、比例和动态准确性 |
| 多次演示初始化 | 当前重新进入准备/播放不会自动重新校准整个估计器 | 比较同进程连续演示与重启后演示；拟在静止承重窗口增加偏置/速度检查，必要时连同参考坐标一致地重置。播放中不直接清零位置或偏置 |

先用诊断数据定位偏置、漂移、错时或接触切换，再调整参数。增加低通可能减小曲线抖动，同时增加延迟；调小协方差也不等于提高真实精度。

## 优先级二：本体融合与接触判断

当前每轴独立估计 `[身体位置, 速度, 世界系加速度偏置, 左脚位置, 右脚位置]`，姿态不在滤波状态中。拟比较接触辅助的误差状态 EKF / InEKF，联合处理姿态、位置、速度、陀螺仪偏置、加速度计偏置及接触点的不确定性。

优先让候选估计器旁路运行：接收相同输入并记录结果，仍由当前估计器驱动 policy。通过静态、受控运动和仿真真值比较之后，再评估闭环切换；更换算法本身不代表精度提升。

接触处理同步改进：

1. 当前由准静态关节力矩反推载荷，再用高度、速度和阈值判断接触；摆腿惯性、力矩比例误差和脚滑都可能影响结果。评估更完整动力学/动量观测器，或有条件时增加足底压力/六维力传感器。
2. 根据惯性预测与足端观测的不一致程度识别可疑接触、降低权重；不要持续把滑动脚当作静止约束。
3. 对脚掌滚动、接触点切换和落地冲击评估平滑权重，避免硬切换引入速度或位置突变。力传感器能补充接触信息，但不能单独保证脚没有滑动。

仅凭惯性和腿部接触，全局位置与航向缺少独立约束，仍可能累计漂移。接触辅助 InEKF 的原理、可观测性及双足实验可参考[论文](https://arxiv.org/abs/1904.09251)和[作者 C++ 实现](https://github.com/RossHartley/invariant-ekf)。这些是方案依据，不是 X1 的效果保证。

## 优先级三：外部定位约束

| 方案 | 用途 | 接入要求 / 局限 |
| --- | --- | --- |
| 动捕＋本体融合 | 实验室独立精度参照，也可辅助闭环 | 标定刚体到 base 的变换、时钟和延迟，检查遮挡与姿态质量；速度通过合适的滤波/融合获得，不直接差分带噪位置喂给 actor |
| 激光惯性里程计＋本体融合 | 在实际演示场地抑制累计漂移 | 完整三维状态、坐标变换和延迟补偿；环境退化时降低权重，地图重定位/回环不能直接令 policy 输入跳变 |
| 视觉惯性或视觉标记定位＋本体融合 | 有相机且场景满足条件时的替代方案 | 验证光照、运动模糊、遮挡、可见范围、外参和延迟，不能仅凭静态定位效果判断舞蹈时精度 |

推荐结构为：本体估计高频传播，外部观测按采样时刻纠偏，再输出到当前时刻。避免把滞后的外部位姿与最新编码器直接拼接。如果定位传感器安装在相对骨盆会运动的躯干或头部，需使用对应时刻的关节运动学转换。

项目已有 FAST-LIO2，但目前 `publish_odometry` 没有填写 twist；导航桥接又会压平姿态，不能直接作为舞蹈状态。需保留完整 `odom → base_link` 位姿、机身原点 body 线速度，以及与 IMU 一致的世界 yaw/时基，或通过专用融合适配层接入。现有外部 `state_source: odometry` 模式可复用接口；具体融合尚未实现。[FAST-LIO 官方实现](https://github.com/hku-mars/FAST_LIO)

默认本体估计直接在控制器内存中传递结果，`/dance/odometry` 只是检查输出。提高精度不要求增加 ROS 回环；外部状态可采用 ROS 接口或进程内接口，关键是数据语义、时间和融合正确。

## 验收与 154 维模型接入

### 独立精度验收

建议按以下顺序采集，覆盖多次重复、不同初始朝向，以及同进程/重启两类情况：

1. 静站：比较速度零偏、抖动、姿态稳定性和位置趋势，核对初始化偏置与时间差。
2. 受控运动：重心移动、脚掌滚动、抬脚、慢走往返，检查接触切换、滑移及杆臂补偿。
3. 舞蹈：单独统计前两秒和整段表现，并对齐实际参考帧。

有独立参照时，统计位置/速度 RMSE、姿态角误差、末端漂移、延迟、P95/峰值误差及多次重复分布；外部参照本身也需核实精度和时基。只做起始坐标对齐，避免用全程轨迹拟合掩盖漂移。没有外部参照时只能确认静态和内部一致性，无法确认完整动态估计误差。

在仿真中对各输入分别注入偏置、噪声、延迟和漂移，确定当前策略容忍范围后再制定验收阈值。历史 MuJoCo 的约 1.8–2.1 cm 位置 RMSE、0.013 m/s 速度 RMSE 只适用于原记录中的有限场景，不能作为真机保证。

### 154 维模型训练完成后的交付与适配

- 保留实际训练任务、完整环境/runner 配置、代码版本、依赖版本、动作与模型资产 hash，以及 checkpoint 和对应归一化统计；确认实际 actor 为 154 维及观测顺序，不能仅依据任务名判断。
- 按新 checkpoint 核对网络结构、归一化公式/eps、关节顺序、默认角、PD、动作缩放、参考频率、单帧/历史输入及 reset 设置。训练存在覆盖参数时以实际快照为准。
- 适配导出器、模型维数/观测语义校验、C++ 观测拼接、仿真读取器及诊断 schema，新增独立 PyTorch 与部署推理数值对照。160 / 154 维模型应能明确识别，错误组合应拒绝加载。
- 设计 154 维的准备/播放状态接入，明确身体估计仍用于哪些就绪或诊断功能，再决定是否解除 actor 对位置/速度估计链路的间接等待。相对姿态仍需腰部 FK；初始 yaw 对齐和参考时钟须与训练一致。
- 完成离线回放、接管仿真和 Ubuntu 原生验证后，再比较真机重复演示；本次仅记录计划，尚未做上述代码适配。

### 对照设计与结果解释

| 对照 | 主要目的 |
| --- | --- |
| 同一 160 维权重：仿真真值输入 vs 估计输入 | 在相同模型、参考和成组初始条件下评估估计链路影响 |
| 同一组有独立参照的记录：160 维 actor 估计输入 vs 替换为参照状态的输入 | 离线观察输入误差引起的 action 差异；不会验证替换后真实闭环是否稳定 |
| 160 维模型 vs 新训练的 154 维模型 | 比较各自部署路线的接管成功率、完整播放率、倾角、关节跟踪、真实路线/漂移和多次重复分布 |

160 / 154 维比较尽量固定参考动作、准备流程、地面、PD 和试验条件，并记录训练差异。两套权重不同，若 154 维更稳定，只能先说明该部署路线表现更好，不能据此单独认定原模型的失败原因。

当前参考动作本身包含约 3 m 的水平位移，跳到边缘不自动意味着定位漂移；路线效果须对照对齐后的参考和实际测量。154 维模型去掉位置误差后仍应检查该项，避免只用完成时长评价。
