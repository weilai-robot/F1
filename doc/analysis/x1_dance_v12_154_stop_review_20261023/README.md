# X1 v12 154 维舞蹈结束与稳定停止审查（2026-10-23）

这是修复前提交 `0c41890` / 子模块 `64220c5` 的审查基线。后续实现和当前验证见[收尾与站稳](../../BeyondMimic_X1_154维收尾与站稳.md)。

历史结论：部署单轮播放 647 帧、50 Hz，名义时长 12.94 秒。正常 Guide 后先过渡 4 秒、连续就绪 4 秒，再播放；因此从 Guide 到结束至少约 20.94 秒，就绪不足会延后。A/B 与人工等待另计。

当前代码会在参考播放结束时自动进入 keep，但没有完成稳定收尾验证；补充数值仿真在三个朝向下均观察到切换后倒地。当前实现不具备可验收的自主稳定停止能力。

## 高优先级发现

1. `DanceController::Update` 在 647 帧播放完成后仅设置 finished，不检查身体/关节速度、双脚支撑或动态稳定性。`ControlModule` 随即在同一控制拍进入 keep。
2. `PDController::RestartController` 捕获切换瞬间的实测关节角，keep 直接维持这些角度、目标速度为 0，并立刻采用 keep 的高 PD 增益。没有减速轨迹、落脚/重心调整、站姿恢复或运行中的平衡策略。keep 阶段也不会继续调用舞蹈控制器的 35° 倾角保护。
3. 参考动作最后一帧最大关节速度约 2.857 rad/s（左膝），参考 base 偏航角速度约 −2.520 rad/s；动作素材本身没有以静止站立结束。训练的 motion command 在动作耗尽后重采样/重置，没有专门的真实物理停止动作。
4. 既有 `sim_beyondmimic_x1.py` 的 completed 判据只要求播放无故障并生成全部帧，仿真在最后一个舞蹈物理步后返回。此前三组“647 帧通过”均不覆盖进入 keep 后的保持阶段。

## 补充仿真

在原始部署探针最后追加 8 秒：沿用同一模型、最终物理状态、关节 effort 限幅；捕获实测 q 为固定目标，立刻使用 YAML 中 pd_keep 的 kp/kd，目标速度为 0。原有播放统计与之前保存的报告逐项完全一致。没有修改生产源码或策略权重。

三组切换时最大关节速度均约 2.31–2.33 rad/s，均不满足双脚同时触地；随后倾角接近 90°、base 高度降至约 0.131 m。以上是理想关节 PD 数值仿真的失稳结果，不能把 0.87–0.89 秒直接当作真实机器人倒地时间。

原始 JSON 包含 0.5 秒间隔的停止后状态采样。`com_support_margin_at_switch_m=-1` 是接触点不足的哨兵值，不代表实际负一米裕度。模型没有位置/线速度 actor 输入，但这些指标在仿真中用真值独立评估。

`stop_probe_snapshot.py` 是产生报告的原始实验脚本，包含本机绝对路径；`sources_and_method.json` 记录脚本、模型与相关生产文件 SHA256。它通过 AST 在生产 Python 探针 return 前追加实验，未更改生产源码。

## 后续修改方向

需要专门设计并验证收尾：使动作末段减速并完成落脚，确认支撑和低速度，再由经过验证的站立/平衡控制器接管。仅把 keep 换为 stand，或延长/重复最后一个动态参考帧，尚不能证明能稳定停下。验收应包含切换后至少 5–10 秒的保持、多朝向与扰动对照，再执行目标 Ubuntu C++/ROS/DCU 和真机验证。
