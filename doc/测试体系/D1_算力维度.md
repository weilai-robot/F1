## 1. 判定框架

"大脑资源够不够用"在本维度拆为 3 问，**全部 PASS 才算够用**：

| # | 问题 | 一句话判据 |
|---|------|-----------|
| Q1 | 大脑自己跑得动吗 | 各模块周期/耗时达标，不被 CPU 排队饿死 |
| Q2 | 系统资源总量够吗 | CPU 无持续排队、内存无压力、无换页、无热降频 |
| Q3 | 大脑拖垮小脑了吗 | 实时核延迟不退化，控制周期无 deadline miss |

## 3. 判定标准

| 指标 | 阈值 | 观测点 |
|---|---|---|
| FastLIO `ave total` | <70ms，30min 无增长趋势 | MOD-01 |
| Open3D `time_this_loc` | 稳定 <100ms | MOD-02 |
| /Odometry 频率 | ≥9.5Hz | TOP-01 |
| Nav2 rate WARN（missed rate / took too long） | 0 次 | nav 日志（D0 §2.2 ④） |
| PSI cpu some avg60 峰值 | ≤5% | SYS-01 |
| swap si/so / OOM / PSI memory | 全 0 | SYS-01/04 |
| MemAvailable 最低值 | >2GiB | SYS-05 |

| 隔离核 CPU4/6 占用 | ≤2% | SYS-02/03 |

| Control 周期 p99 / deadline miss | <200µs / 10min<10 | MOD-03（🚧 待改造） |

## 4. 结论逻辑与降级路径

- **Q3 FAIL** → 资源不够，不得行走。排查：IRQ 亲和（SYS-08）、大脑线程落核（SYS-03）、ONNX 线程数。
- **Q1 FAIL 而 Q2/Q3 PASS** → CPU 总量够、参数过重 → 降 MPPI `batch_size` 600→300、`time_steps` 32→24、local costmap 5→3Hz、global 1→0.5Hz（当前值见 D3 索引 §2），复测。
- **Q2 FAIL** → 先解决内存/热（swap 关闭、散热），再复测。
- **D1 全 PASS 但 D2/D3 FAIL** → 资源够但链路/执行有问题，按 D2 §4 / D3 §5 定位表转维度处置。

## 5. 已知坑

1. **冷启动数据不算数**：FastLIO 耗时随 ikd-tree 增长，判定看 30min 趋势而非开局均值。
2. **E-core 陷阱**：大脑线程被调到 E-core 时"CPU% 不满但周期超标"，用 SYS-03 落核审计确认。
3. **相位叠加尖峰**：10Hz/5Hz 周期任务对齐产生瞬时排队，看 PSI avg10 峰值而非 avg60 均值。
4. **观测自身开销**：actuator_debug 1kHz + bag 是真实负载，PSI 异常先排除观测项（D0 §2.3）。
