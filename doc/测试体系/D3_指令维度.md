# D3 指令维度 — 大脑→小脑指令链路质量

> 状态：📋 bag 数据已到手（2026-09-04，S1–S3 同轮采集）；TC-01/02/05 与 §4 对账/延迟分析待做，TC-03/04/06 需专项动作 ｜ 更新：2026-09-04
> 实现索引：[`D3_指令维度_实现索引.md`](D3_指令维度_实现索引.md) ｜ 场景与采集：[`D0_公共基础.md`](D0_公共基础.md)
> 定位链路前半段：`Nav2 → /cmd_vel → 限速器 → /cmd_vel_limiter → ControlModule(1kHz) → /joint_cmd`，含反馈回传的 DDS 通信质量。

---

## 1. 目标与边界

验证大脑发给小脑的运动指令在**正常工况**下的质量：①实时性（频率/间隔/端到端延迟）②语义正确性（符号/幅度域/限速钳位）③响应性（停止响应）；外加 ④**DDS 通信质量**（传输延迟/断流，含反馈话题）。

> 边界：**故障工况**（断流导致失控、进程死亡）的验证归 D4；看门狗的需求由本维度提出（§7），验证归 D4。

## 2. 链路事实（频率与话题，实现位置见索引 §2）

| 环节 | 频率/约定 |
|---|---|
| Nav2 controller_server (MPPI) → /cmd_vel | 10Hz（`controller_frequency: 10.0`） |
| /cmd_vel → 限速器 → /cmd_vel_limiter | 唯一链路，无旁路发布者 |
| ControlModule 订阅 /cmd_vel_limiter | 事件驱动，写入 controller |
| /joint_cmd 发布 | 1kHz |
| 速度上限 | MPPI `vx_max: 0.4, wz_max: 0.4`；cmd → walk_step_conf 缩放 |

## 3. 测试用例

### TC-D3-01 指令频率与间隔稳定性
bag 记录 `/cmd_vel_limiter`，统计间隔分布（mean/P95/max）与条数对账（10min ≈ 6000 条 ±1%）。判定：均值 100ms ±5%；**max 间隔 <300ms**；缺口 >1% 视为断流转 D4 复核。

### TC-D3-02 端到端延迟
`/cmd_vel` 最后一条 stamp 与其后第一条 `/joint_cmd` 的 bag 接收时间差，减 1ms 控制周期，作为上界（R2 落地前）。判定：上界 <30ms。

### TC-D3-03 速度符号语义
吊装状态，手柄分别给 +x/−x/+yaw/−yaw，记录 `/cmd_vel_limiter` 与 walk_diag 的 cmd 列、base_euler_z 变化方向。判定：指令符号 → 期望摆动方向 → 基座响应方向三者一致；y 向符号约定与 RL 训练侧一致。

### TC-D3-04 限速链路钳位
安全速度下向 `/cmd_vel` 发布超限脉冲（vx=1.0, wz=1.0），记录 `/cmd_vel_limiter` 输出。判定：钳位到 ≤vx_max/wz_max；链路无旁路发布者。

### TC-D3-05 指令幅度域
S2 全程统计 `/cmd_vel_limiter` 幅值分布。判定：无越限；无长期顶满上限（否则参数与场景不匹配）。

### TC-D3-06 停止响应时间
行走中发导航取消（或 cmd_vel=0），从最后一条非零指令 stamp 到 walk_diag 关节速度归零（<0.1 rad/s）。判定：<1s。

## 4. DDS 通信质量分析（S1/S2 对比）

### 4.1 链路完整性与新鲜度（条数对账）

`ros2 bag info` 对账：

| 话题 | 期望（10min） | 判定 |
|---|---|---|
| /joint_states | 600,000 ±1% | 缺口>1% = 丢包/发布塌陷 |
| /actuator_cmd /actuator_states | 600,000 ±1% | 两者必须相等（同循环发布） |
| /joint_cmd | 600,000 ±1% | — |
| /cmd_vel（导航中） | ~6,000 | max 间隔 <300ms |

/cmd_vel 间隔尖峰 >300ms 时，对照同刻 /joint_states 是否也有缺口，区分 Nav2 计算超时与 DDS 断流。

### 4.2 传输延迟（stamp 探针）

用 `/joint_states`（唯一全链路带 stamp 的 1kHz 话题）做探针：延迟 = bag 接收时间 − header.stamp，统计 P50/P95/P99/max 并画时间序列。判定：P99 <5ms；S2 相对 S1 增幅 <2ms。

附加读法：延迟尖峰时刻若与 FastLIO 重帧/MPPI 重算对齐（对照 nav 日志）→ DDS 线程被大脑计算线程挤压——"资源不够"的通信侧证据。
