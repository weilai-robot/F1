## 3. 维度间层级关系

```
                    F1 集成测试体系（本总纲）
                              │
        ┌─────────────────────┼─────────────────────┐
        │ 正常工况验证         │   异常/长期验证       │
        │                     │                     │
        │  D3 指令维度 ──▶ D2 控制维度 ──▶ D5 功能维度 │  D4 安全维度（故障注入）
        │  （链路质量）   （执行质量）   （端到端质量） │  D6 耐久维度（时间退化）
        └─────────────────────┴─────────────────────┘
                              ▲
                    D1 算力维度（横切支撑层）
                    资源底盘：所有维度的结论都必须
                    在"资源够用"前提下才成立
                              ▲
                    D0 公共基础（采集底座）
                    场景 S1-S3 + 统一采集 + 观测点编号总表
                    —— 一次跑、多维用
```

**数据流视角**：一条指令的旅程 `Nav2 → /cmd_vel → 限速器 → ControlModule(1kHz) → /joint_cmd → EtherCAT → 电机`——D3 管前半段，D2 管后半段，D5 管全程结果，D1 保证全程有资源可用，D0 提供共享采集底座，D4/D6 分别验证异常和长期下 D1–D5 结论是否仍然成立。

## 4. 公共约定摘要（完整版见 D0 §3）

1. **场景复用**：S1 仅小脑 / S2 小脑+导航 / S3 S2+压力，各维度测试挂同一采集（D0 §2），一次跑、多维用。
2. **时钟源**：三套数据体系时钟不兼容，跨体系对齐前必读 D0 索引 §3。
3. **一票否决**：任何维度的一票否决项 FAIL，整轮测试判 FAIL，不进入下一场景。
4. **观测点编号**：SYS/MOD/TOP/DATA 编号的唯一权威总表在 D0 索引 §1，明细在各归属维度索引。

## 6. 文档维护规则

- 新增/变更维度文档时同步更新本总纲的罗盘、结构树与层级图。
- 各维度文档头部必须带状态标签与最后更新日期。
- 详细技术内容写在各维度文档；总纲只维护"有什么、什么状态、在哪"。
- 方案与索引分离：代码/配置变动只更新对应 `DX_*_实现索引.md`，方案文档不随代码变动。
