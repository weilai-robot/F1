## 3. resource_monitor.sh 用法

```bash
sudo apt install sysstat procps              # 依赖；cyclictest 需 sudo apt install rt-tests
./scripts/resource_monitor.sh 600 /data/f1_obs/S1_xxx/sys   # 时长秒 + 输出目录
sudo WITH_CYCLICTEST=1 ./resource_monitor.sh 600 <dir>      # 加测 SYS-07（挂 CPU4）
ROS_SETUP=/opt/ros/humble/setup.bash ./resource_monitor.sh ...  # 可选：自动采话题频率
```

结束时输出 PASS/FAIL 判定报告 `report.txt`（含 PSI/swap/隔离核污染/温度/OOM/cyclictest 自动判定）。
> 2026-09-01 修复 report.txt 中 mpstat 解析 bug（CPU 号在第 2 列而非行尾，原隔离核检查恒 NA→假 PASS）。
> 2026-09-02 B4 干跑再暴露三处 report.txt 路径 bug，已修复（`d1_judge.py` 字段级解析不受影响）：
> ① mem.log 解析取 `$2` 整串 `MemAvailable=NNNNMB` 数值强转恒 0 → 永远 FAIL（本次干跑的 "0.00MB" 即此）；
> ② pidstat/mpstat/vmstat 无限时长被 SIGTERM kill → stdio 缓冲丢失 + sysstat `Average:` 汇总块只在自然结束才输出 → 隔离核/最忙核恒 NA（假 PASS）；改为有限次数（DUR/INTERVAL−1）+ `LC_ALL=C` 自然退出；
> ③ PSI 解析不分段，mem-full / io 的 avg60 会串进 "PSI cpu" 名下（实测复现：造数 mem full=3.00 被旧解析报成 cpu 3.00）；cpu/mem 各限定自身段落。

## 4. d1_judge.py 用法（D1 判定自动化）

```bash
# 采集完成后（目录名需以 S1/S2/S3 开头，DC/cyclictest 阈值按场景自动切换）
python3 scripts/d1_judge.py /data/f1_obs/S1_* /data/f1_obs/S2_* /data/f1_obs/S3_*
# 输出: 终端 + 第一个目录下 d1_judge.md；退出码 0=全PASS 1=有FAIL 2=全无数据
```

输入依赖（缺哪项对应行显示 `—`，不阻塞其他判定）：
- `sys/` 六个采集文件（resource_monitor.sh）
- `nav_tmux.log`（FastLIO ave total / Open3D time_this_loc / Nav2 超时 WARN 解析）
- `ctrl_period_*.csv`（R5）、`ecat_stats_*.csv`（R3/R4）——按 D0 §2.2 ④ 拷入 RUN 根
- 可选 `topic_hz__Odometry.log`
- miss/overrun 采用**滑动 10min 窗口**计数（60 行 × 10s），与判定标准"10 分钟内 <10 次"严格对应

夹具回归：`python3 scripts/d1_judge.py scripts/tests/d1_fixture/S1_x scripts/tests/d1_fixture/S2_x` 应得 S1 全 PASS / S2 全 FAIL / exit=1。
