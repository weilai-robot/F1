# 01 测试执行手册 — 按序测试步骤

> 状态：✅ 首版（基于 2026-09-02 现有代码与脚本整理）｜ 维护规则：脚本用法/启动顺序变动时更新本文档
> 定位：[00_测试体系总纲](00_测试体系总纲.md) 的**执行入口**——把 D0–D6 方案与 `scripts/` 现有工具串成一条可按序执行的步骤线。
> 分工：本文档只管"**按什么顺序跑、每步跑什么命令、过不过**"；测什么/阈值/机理见各 DX 方案文档。

---

## 0. 步骤总览与执行原则

| 阶段 | 内容 | 动机器人 | 依据 | 产物 |
|---|---|---|---|---|
| A | 前置准备（安全/环境/依赖） | 否 | D0 §3、配置指南 §3/§8 | 环境核验结论 |
| B | 构建与工具自检 | 否 | 配置指南 §8 阶段 1 | build 产物 + 工具冒烟通过 |
| C | 仿真层测试（真机门禁） | 否 | D5 §2 | reports/ 指标报告 |
| D | 真机静默与受控使能 | 是（吊装） | 配置指南 §8 阶段 2–4 | 总线/调度/安全行为核验 |
| E | 三场景采集 S1→S2→S3 | 是（吊装） | D0 §2 | `/data/f1_obs/<场景>_*` 完整数据 |
| F | 分析与判定 | 否 | D1/D2/D3 方案 | d1_judge.md + 各维度结论 |
| G | 待建项（D4/D6/长跑） | — | 总纲 §5 | — |

**执行原则**：
1. **顺序不可跳**：C 是真机门禁（仿真 FAIL 不上真机）；D 是 E 的前提；E 内 S1→S2→S3 顺序推进。
2. **一票否决即停**（D0 §3.4）：WKC link lost、摔倒、失控任一出现，当轮判 FAIL，修复后从该场景重跑。
3. **判定前提**：SYS-08 环境快照（isolcpus/governor/落核）不达标时，本轮所有资源类结论无效（D0 §3.6）。
4. 阈值以各 DX 方案文档为准，本文只内联"步骤通过/不通过"的门禁值。

### A2 主控环境核验（判定前提 SYS-08）

```bash
grep -o 'isolcpus=[^ ]*' /proc/cmdline        # 已配即过（实测部署 isolcpus=4,5,6,7，未配置→本轮资源结论无效）
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor   # 期望: performance
swapon --show                                  # 期望: 空（swap 已关，配置指南 §6.2）
cat /sys/kernel/realtime 2>/dev/null           # PREEMPT_RT 内核确认
```

> **2026-09-02 部署实测与本轮决策记录**：
> - 实机 isolcpus=**4,5,6,7**（整核对隔离，含超线程兄弟 5/7——比配置指南 §3.4 写的 4,6 更严格，且与指南 §7 systemd 服务亲和"排除 4,5,6,7"一致）。判定以实际 cmdline 为准，**不要**按指南改回 4,6。
> - swap 已关闭（swapoff + fstab 注释 `/swapfile` 行）。
> - ⚠️ **governor 保持 powersave、`intel_pstate=disable` 缓办**（决策 2026-09-02：首轮实测不改动，先取未调优基线）。两项合并为同一观察窗口。
>   **后果（按 D0 §3.6）**：governor≠performance 时 SYS-08 不达标 → 本轮所有资源类结论标注 **"powersave 条件下"**，非作废——若 S1 全 PASS 则证明该工况够用，两项缓办永久关闭；若挂，按下面路径处置。
>   **复看通道**：SYS-06 每 5s 的 `cpu4_freq` 序列（thermal.log）量化频率行为（注意：intel_pstate+HWP 下 powersave 并非锁低频，负载时仍会升频，实际行为以数据为准）。
>   **触发条件与处置序**：S1 中 cyclictest max 或 ctrl_period p99/miss 超标 **→ 第一步仅置 performance governor（运行时命令，无需重启）复跑 S1；若仍超标 → 第二步补 `intel_pstate=disable`（GRUB，需重启）再复跑**。一步一变量，不复测就下不了结论。

### A3 依赖与磁盘

```bash
sudo apt install -y sysstat procps rt-tests    # resource_monitor.sh 依赖（cyclictest 需 rt-tests）
df -h /home/robot                              # 数据盘余量门禁 ≥50G（见下方偏差记录）
mkdir -p /home/robot/f1_obs                    # 测试数据专用目录（DATA_ROOT）
```

> **偏差记录 2026-09-02（数据盘）**：D0 §2.2 原则要求"录到非系统盘"，但主控实测为**单 NVMe 盘**（476G 单分区，余 298G，ROTA=0），无第二块盘。经评估接受"系统盘专用目录"方案：
> - bag ~4MB/s 顺序写对 NVMe 延迟影响可忽略；**PSI io（SYS-01）实测兜底**——若 S1/S2 出现持续非零 io 压力，升级为外接 USB SSD（ext4）并复跑；
> - 写满风险用跑前余量门禁 **≥50G** + 每轮结束归档清理控制；
> - D6 长跑不全程录 bag（D6 索引既有约定），不受影响。

## 阶段 D：真机静默与受控使能（吊装前提）

> 依据配置指南 §8 阶段 2–4。本阶段含两项**安全行为验证**（Ctrl+C 退出、拔网线 WKC 报错）——D4 安全维度的既有雏形。

### D1 无使能总线测试（阶段 3）

```bash
cd build
sudo setcap cap_net_raw=ep ./aimrt_main          # 重拷二进制后需重做
./aimrt_main --cfg_file_path=./cfg/x1_cfg.yaml   # 或 bash run.sh
```

依次核验（配置指南 §8 阶段 3 清单）：

1. 日志出现 `N slaves found and configured` + `Operational state reached`；
2. 线程调度：`ecat_io_loop → FF:90`、`rl_control_pub_thread → FF:80`，绑定指定 P-core；
3. `ros2 topic hz /joint_states`、`/imu/data` 正常流动；
4. 安全行为：Ctrl+C 正常退出；**断开 EtherCAT 网线 → 日志报 WKC 错误**（D4 雏形，通过后恢复网线）。

任一不符 → 停，按配置指南 §4/§7 排查，禁止进入 D2。

### D2 受控使能（阶段 4，吊装）

```bash
# 统一用脚本切模式（内部持续发 ~2s；勿用 ros2 topic pub --once——DDS 发现未完成会丢，
```

### D3 stand 稳态观察（≥2min）

- 机器人姿态平稳无下沉/抖动；
- `test_logs/` 目录开始正常落盘。

## 阶段 E：三场景采集（D0 §2，一次跑多维用）

### E0 每场景统一采集序列（S1/S2/S3 相同骨架）

```bash
# ① 目录规范（目录名必须以 S1/S2/S3 开头——d1_judge.py 按此识别场景）
#    DATA_ROOT 按部署实测定为 /home/robot/f1_obs（单 NVMe 系统盘专用目录，偏差记录见 A3）
DATA_ROOT=/home/robot/f1_obs
RUN=$DATA_ROOT/S2_$(date +%m%d_%H%M)          # S1/S3 场景相应改前缀
df -h $DATA_ROOT | tail -1                    # 跑前门禁：Avail ≥50G，不足先归档清理旧数据
mkdir -p $RUN && cd $RUN

# ② 系统资源采集（后台，600s；S3 同步加 cyclictest 时用 sudo WITH_CYCLICTEST=1）
<F1>/scripts/resource_monitor.sh 600 $RUN/sys &

# ③ rosbag（S1 也录——空载基线；不录点云大流量话题）
ros2 bag record -o $RUN/bag \
  /cmd_vel /cmd_vel_limiter /joint_cmd /joint_states \
  /actuator_cmd /actuator_states /imu/data \
  /Odometry /livox/imu /odom &

# ④ 执行场景动作（见 E1/E2/E3；walk_diag 在进入 walk 态后自动触发，无需操作）

# ⑤ 结束后留档（walk_diag/ctrl_period/ecat_stats 落点 = aimrt_main 启动目录）
journalctl -u f1-motion-control --since "-12min" > $RUN/aimrt_journal.log 2>/dev/null \
  || cp <aimrt_main日志目录>/*.log $RUN/
tmux capture-pane -p -t f1_nav_real -S -100000 > $RUN/nav_tmux.log 2>/dev/null
cp <aimrt启动目录>/test_logs/data_csv/walk_diag_*.csv     $RUN/ 2>/dev/null
cp <aimrt启动目录>/test_logs/data_csv/ctrl_period_*.csv   $RUN/ 2>/dev/null
cp <aimrt启动目录>/test_logs/ecat_stats/ecat_stats_*.csv  $RUN/ 2>/dev/null
```

### E1 S1 — 仅小脑（基线：底噪）

1. 小脑单独启动（D1 步骤的命令）；
2. `./scripts/switch_x1_mode.sh walk` 切行走（吊装空走）；
3. 手柄给小幅速度指令（或保持零速踏步）**≥10min**；
4. 采集 walk_diag 空载基线、电机底噪、DDS 延迟底噪（S2 对比的对照组）；
   > 注意：walk_diag 仅 walk 态记录（D2 §7.1），S1 的 stand 段无 walk_diag，靠 bag（DATA-04）补。
5. `./scripts/switch_x1_mode.sh stand` 收尾。

### E2 S2 — 小脑 + 完整导航（工作点）

1. 小脑启动（同上）；
2. 另开终端启动大脑：`./scripts/run_nav_real.sh`（tmux: f1_nav_real；livox+fastlio+nav2）；
3. 确认 TF `map→odom→base_footprint` 已通、ICP 已锁定；
4. 发目标并自动收尾：`./scripts/send_nav_goal_real.sh 1.0 0.0`（walk→goal→stand，防摔）；
   首次联调用 `--ready 1.0 0.0`（zero→stand→walk 全序列）；
5. 重复发点/绕行 **≥10min**（可配合 `record_nav_test.sh --nav -d 120 walk` 做定位分层留档）。

### E3 S3 — S2 + 压力（裕量边界）

1. 同 E2 启动；
2. 叠加压力：`stress-ng --cpu 4 --io 2 --vm 2 --vm-bytes 1G`；
3. 重复导航 **≥10min**；
4. 结束后停掉 stress-ng 再收尾。

### E4 场景间检查点（一票否决）

每场景结束后、进入下一场景前快速检查：

```bash
grep -c "Ecat link lost" $RUN/aimrt_journal.log      # ≥1 → 停，修硬件，本轮作废
grep -c "wkc < expected_wkc" $RUN/aimrt_journal.log  # S1 应为 0；S2>0 记录待 D2 分析
# 机器人未摔倒、无失控（人工确认）
```

## 阶段 F：分析与判定

### F1 D1 算力维度（自动化，先跑这个）

```bash
python3 scripts/d1_judge.py /home/robot/f1_obs/S1_* /home/robot/f1_obs/S2_* /home/robot/f1_obs/S3_*
# 输出: 终端 + 第一个目录下 d1_judge.md（Q1/Q2/Q3 判定表）
# 退出码: 0=全 PASS  1=有 FAIL  2=全无数据
```

**Q3（拖垮小脑）FAIL → 资源不够，不得行走**，按 D1 §4 排查（IRQ 亲和/落核/ONNX 线程数）；
Q1 FAIL 而 Q2/Q3 PASS → 按 D1 §4 降 MPPI 参数（600→300 / 32→24）复测。

### F2 D2 控制维度（总线半自动 + 电机手动）

```bash
# ① 总线（一票否决项）：
grep -c "wkc < expected_wkc" $RUN/aimrt_journal.log   # 0 → PASS
grep -c "Ecat link lost"     $RUN/aimrt_journal.log   # 0 → PASS
# ② DC 同步 / 周期 overrun（ecat_stats_*.csv，阈值: DC <1µs(S1)/<5µs(S2)；overrun 10min<10）
# ③ 控制周期（ctrl_period_*.csv: miss_cnt 滑动 10min 窗口求和 <10；p99<200µs）
```

电机执行分析（跟踪误差/滞后/力矩/kp-kd）按 [D2_控制维度.md](D2_控制维度.md) §4 手册执行：
S1 底噪 vs S2 行走对比（RMS 相对 S1 >3× → 执行层退化），工具为 plotjuggler 或脚本手动分析（bag_analyze.py 未实现前）。

### F3 D3 指令维度（bag 手动分析）

```bash
ros2 bag info $RUN/bag        # 条数对账（/joint_states 10min≈600,000±1%；cmd/actuator 对相等）
```

间隔分布 / stamp 延迟（P99<5ms）/ 钳位 / 停止响应用 plotjuggler 按 [D3_指令维度.md](D3_指令维度.md) §3–§4 执行；TC-D3-03/04 需在 E1/E2 中手动布置（手柄四方向符号核对、超限脉冲钳位观察）。

### F4 D5 功能维度（真机用例——方案就绪、工具待建）

现有可用最小流：E2 数据 + `send_nav_goal_real.sh` 单点 + 人工/半自动判读（到达误差<0.5m、euler<45° 未摔）。
完整 5 用例（TC-D5-01..05）依赖 nav_test_runner.py 真机模式（待建，见 D5 索引 §3）。

### F5 结论归档

- 判定表（d1_judge.md）、各维度人工结论、异常截图 → 存入对应 `$RUN/`；
- 结论格式：每维度一行 PASS/FAIL + 一句话证据，回填到当轮测试记录；
- 仿真报告归档 `reports/`（自动），真机数据留 `/data/f1_obs/`（不进 git）。
