# D5 功能维度 — 导航任务完成质量

> 状态：📋 方案就绪（仿真侧 ✅ 已实现，真机侧待实施）｜ 更新：2026-09-01
> 实现索引：[`D5_功能维度_实现索引.md`](D5_功能维度_实现索引.md) ｜ 场景与采集：[`D0_公共基础.md`](D0_公共基础.md)
> 定位：端到端任务质量——"跑得动"（D1）"执行好"（D2）之后，还要"跑得对"。

---

## 1. 目标

验证大脑下达的导航任务被正确完成：到达目标、不撞、不摔、定位不漂、运动平滑。

## 2. 现状：仿真侧已实现（可直接复用的资产，位置见索引 §1）

| 资产 | 内容 |
|---|---|
| **指标计算器** nav_test_runner.py | P0：摔倒率、碰撞次数；P1：成功率、位置精度、SLAM 漂移；P2：速度 jerk、路径效率、完成时间；性能：RTF、CPU/内存 |
| 漂移诊断 drift_check.py | FastLIO /Odometry vs MuJoCo GT 逐帧配对 |
| CI 编排 ci_nav_test.sh | Xvfb → 全链路启动 → 健康检查 → 场景批量 → 报告归档 |
| 场景库与历史 reports/ | 场景化结果留档（如 A_straight_5m_20260714） |

关键阈值（仿真版）：摔倒 = base_z<0.35m 或倾角>45°；成功 = 未摔+零碰撞+距目标<0.35m。

## 3. 真机迁移方案：GT 缺失下的指标替换

替换原则：**用真机已有的独立测量源（Open3D ICP 定位、IMU、walk_diag）替代 GT**，指标分级框架不变。

| 仿真指标 | 真机替代 | 精度损失 |
|---|---|---|
| 摔倒检测 | **walk_diag 的 base_euler + IMU**（roll/pitch>45° 判倒） | 低 |
| 位置精度 | **Open3D ICP 定位（map 系）** vs 目标点，阈值放宽 0.35→0.5m | 中（含定位自身 ~cm 级误差） |
| 碰撞 | **最小障碍间距**：costmap 中机器人足迹到最近障碍全程 min>0.3m；真机实碰人工记录 | 高（间接指标） |
| SLAM 漂移 | **回环法**：走回起点，ICP 起终点差/总路程；辅助 /Odometry 与 ICP 一致性残差 | 中（只测闭环漂移） |
| 速度跟踪/jerk | ICP 定位差分速度 vs cmd_vel（低频近似）；jerk 用 cmd_vel 差分 | 中 |
| RTF | 不适用（删除） | — |

## 4. 真机测试用例（首版最小集）

| 用例 | 场景 | 判定 |
|---|---|---|
| TC-D5-01 直线到达 | 前进 3m，吊装/保护下 | 到达误差<0.5m；未摔；完成<2×仿真预期 |
| TC-D5-02 原地转向 | ±90° 转向 | 终态 yaw 误差<10°；无持续漂移 |
| TC-D5-03 避障绕行 | 路径中放置单障碍 | 绕行成功且全程最小间距>0.3m |
| TC-D5-04 回环漂移 | 走方形回原点 | 闭环位置误差/总路程 <3%（实测后收紧） |
| TC-D5-05 长直线 | 5m+（对应仿真 A_straight_5m） | 同 01，附加中途无 >1s 零速停顿段 |

每用例产出：result.json（对齐仿真格式）+ 关联 walk_diag + bag。

## 5. 数据源与工具

- **ICP 定位**：`map → odom` TF（Open3D，唯一发布者）——真机唯一全局位置真源（位置见索引 §2）。
- **walk_diag（DATA-01）**：IMU/基座姿态（摔倒判定）——明细见 D2 索引 §2。
- **cmd_vel / costmap**：bag（对齐 D0 §2.2 采集，一次跑多维用）。
- **工具**：nav_test_runner.py 增加真机模式（去 GT 化：订阅 TF + walk_diag 后处理），保持指标框架与 reports/ 格式兼容，历史可比。

## 6. 已知局限与风险

1. ICP 定位误差是测量噪声底——0.5m 阈值含 ~10cm 级测量不确定度，不可再收紧。
2. 间接碰撞指标依赖 costmap 质量，需先通过 D1 Q1 检查（costmap 更新正常）。
3. 真机场景库首版只做 5 个最小用例；扩库在 D7 平台维度建设时一并考虑。
