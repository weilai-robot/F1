## 1. 数据链路全景

```
Nav2 controller(10Hz) ──/cmd_vel──▶ 限速器 ──/cmd_vel_limiter──▶ ControlModule(1kHz订阅)
   ──计算──▶ /joint_cmd(1kHz) ──▶ dcu_driver ──EtherCAT(1kHz)──▶ 电机驱动器 ──▶ 电机
                                                      │
                        /joint_states, /actuator_states, /actuator_cmd(1kHz) ◀─反馈
```

| 链路段 | 归属维度 |
|---|---|
| Nav2 → /cmd_vel → 限速器 → ControlModule（指令前半段） | D3 指令维度 |
| /joint_cmd → EtherCAT → 电机 → 反馈（执行后半段） | D2 控制维度 |
| 端到端任务结果（到达/避障/摔倒） | D5 功能维度 |
| 全程资源可用性（CPU/内存/热/实时性） | D1 算力维度 |
| 失效工况 / 长时退化 | D4 安全 / D6 耐久 |

## 2. 三场景采集流程

### 2.1 场景矩阵（机器人吊装；压力测试期间 `enable_actuator: false`）

| 场景 | 运行内容 | 用途 |
|---|---|---|
| S1 | 仅小脑 | 基线（含 walk_diag 空载基线、电机底噪、延迟底噪） |
| S2 | 小脑 + 完整导航 + **实际下发导航目标** | 正常工作点判定 |
| S3 | S2 + `stress-ng --cpu 4 --io 2 --vm 2 --vm-bytes 1G` | 最坏情况，裕量边界 |

### 2.2 每场景统一采集动作

```bash
# ① 目录规范：每场景独立目录，录到非系统盘
RUN=/data/f1_obs/S2_$(date +%m%d_%H%M)
mkdir -p $RUN && cd $RUN

# ② 系统资源采集（后台，10 分钟；产物 sys/ 下，见 D1）
/path/to/scripts/resource_monitor.sh 600 $RUN/sys &

# ③ rosbag（S1 也要录：空载基线；不录 /livox/lidar 与 /cloud_registered_body 大流量话题）
ros2 bag record -o $RUN/bag \
  /cmd_vel /cmd_vel_limiter /joint_cmd /joint_states \
  /actuator_cmd /actuator_states /imu/data \
  /Odometry /livox/imu /odom &

# ④ 日志留档（结束后）
journalctl -u f1-motion-control --since "-12min" > $RUN/aimrt_journal.log 2>/dev/null \
  || cp <aimrt_main日志目录>/*.log $RUN/
tmux capture-pane -p -t f1_nav_real -S -100000 > $RUN/nav_tmux.log 2>/dev/null
cp <aimrt启动目录>/test_logs/data_csv/walk_diag_*.csv     $RUN/ 2>/dev/null   # walk_diag 落点随启动目录
cp <aimrt启动目录>/test_logs/data_csv/ctrl_period_*.csv   $RUN/ 2>/dev/null   # R5 控制周期统计
cp <aimrt启动目录>/test_logs/ecat_stats/ecat_stats_*.csv  $RUN/ 2>/dev/null   # R3/R4 总线统计
```

### 2.3 观测负载注意事项

- `actuator_debug` 1kHz 发布是观测性开销，**三个场景全程保持开启**（把这笔开销测进去才是真实裕量）；长期生产再关闭。
- bag 约 1–2 GB/10min，确认非系统盘余量 ≥5GB。
- `ros2 topic hz` 自身占 CPU，跑在普通核，勿挂隔离核终端。

## 3. 公共约定

1. **场景复用**：各维度测试挂同一场景采集（§2），产物按维度各自分析，不重复采集。
2. **数据目录**：`/data/f1_obs/<场景>_<日期时间>/`，子目录 `sys/`（D1）、`bag/`（D3/D5）、walk_diag CSV（D2）、报告入根。
3. **时钟源**：三套数据体系时钟不兼容（steady vs wall），跨体系对齐前必读 [`D0_公共基础_实现索引.md`](D0_公共基础_实现索引.md) §3；改造落地前不做跨体系时间相减。
4. **一票否决**：任何维度的一票否决项 FAIL（WKC 丢帧、摔倒、失控等），整轮测试判 FAIL，不进入下一场景。
5. **安全前提**：吊装/急停在手/`enable_actuator` 受控，见 [`../同机部署配置指南.md`](../同机部署配置指南.md) 第 8 节。
6. **判定前置**：SYS-08 环境快照（isolcpus/governor/线程落核）不达标时，该轮所有维度的资源类结论无效。
