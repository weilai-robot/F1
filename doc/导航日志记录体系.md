## 1. 体系总览：工具分工

| 工具 | 入口 | 定位 | 何时用 |
|------|------|------|--------|
| **nav_debug 三件套**（主入口） | `scripts/nav_debug_record.sh` | 导航行为复盘：规划→控制→执行三段证据链 | **任何行走异常的首要动作** |
| `record_nav_test.sh` | 同名脚本 | 定位分层诊断（LIO 暴走 / ICP 跳变 / TF 断链） | 怀疑定位漂移时 |
| `capture_nav_issue.sh` | 同名脚本 | 事后现场抓取（lifecycle/频率/tmux 日志） | 异常已发生、系统还在跑 |
| `walk_diag`（小脑内置） | 自动触发 | 关节级执行细节 100Hz（`build/test_logs/data_csv/`） | 怀疑 RL 步态本身 |
| `axis_check.py` | 同名脚本 | GT/FastLIO/TF 三源朝向对比（仿真） | 坐标系改动后回归 |
| FastLIO `runtime_pos_log` | 配置已开 | LIO 内部耗时/位姿 | 性能/漂移分析 |

## 2. 快速开始（nav_debug）

```bash
# 前提: run_nav_real.sh 栈已起 + 小脑已用 x1_cfg_real_nav.yaml 启动 + 机器人已 stand
./scripts/nav_debug_record.sh -d 120 walk_stuck     # 开录 (Ctrl+C 亦可, 自动收尾)

# 另一终端: 切模式 + 发目标

python3 scripts/nav_debug_plot.py reports/nav_debug/<目录>
```

## 3. 数据流与坐标系约定

```
map 系   : /plan (NavFn, 1Hz) ──────────────┐
                                            │ map→odom TF (open3d ICP, 2Hz)
odom 系  : /odom + odom→base_footprint ──┐  │
          /nav_debug/mppi_optimal_traj   │  │ 统一拼到 map 系
          /transformed_global_plan       ├──┘
          /local_costmap                 │
数值     : /cmd_vel → /cmd_vel_limiter ──┘ (叠加到轨迹上)
原始链   : /Odometry (FastLIO, camera_init) — 与 /odom 对照分离 bridge 层问题
定位质量 : /odom2map, /localization_3d_confidence (ICP 矩阵/fitness, 2Hz)
状态机   : /walk_mode /stand_mode /zero_mode /idle_mode /keep_mode (事件)
```

**关键机制**：MPPI 局部轨迹没有现成话题（Humble 无 `/local_plan`），由 `nav_debug_logger.py`
保活订阅 `/trajectories` 并提取 "Optimal Trajectory" 命名空间 → `/nav_debug/mppi_optimal_traj`
（约 3KB/帧 vs 原始 300KB/帧）。后处理用录到的 map→odom TF 逐帧把 odom 系数据变换到 map 系。

## 5. 自动判据：故障模式 → 证据

summary.md 自动产出以下判据（阈值可用 CLI 参数调）：

| 故障假设 | 判据（summary 章节） | 图形证据 |
|---|---|---|
| **H1 近场鬼影障碍+膨胀压 vx**（blind 0.9 × raytrace_min 1.2 × infl 0.7） | "卡停 ∩ vx≈0" 区间 + 期间指令统计 | map_overlay 卡停点被红/橙包围且现实无障碍 |
| **H2 map→odom 跳变** | "跳变 N 次"时刻表（Δxy/Δyaw/帧间隔） | cmd_vel.png 紫点划线与 vx 骤降对齐 |
| **H2 前兆：ICP 冻结** | fitness 低于 0.9 的冻结区间 | fitness 行绿底 |
| **H3 twist≡0 引发指令震荡** | 数据质量告警"/odom.twist 恒 0" + vx 摆动 | cmd_vel.png vx 高频抖动 |
| **H4 RotationShim 原地转** | "Shim 原地旋转区间"（轨迹静默∩wz 非零） | wz 恒 ±0.4、MPPI 轨迹断流 |
| **H5 状态机抢占（假卡停）** | 模式切换事件落在卡停区间内 | 黑三角标记 |
| **RL 死区**（vx<0.05 只踏步） | 卡停区间内 |vx|max 统计 | vx∈(0.02,0.05) 持续 |
| bridge 层错误（mount 等） | /odom 与 fastlio_odom.csv 趋势不一致 | — |

**排查决策树**（summary 尾部自动给出）：
1. `/cmd_vel`≈0 → MPPI 输出零速 → 查 costmap/局部轨迹/局部极小（H1）或 Shim（H4）；
2. `/cmd_vel` 非零但 limiter≈0 → odom_bridge 限幅器；
3. limiter 非零但实测≈0 → 下位机/RL（含死区、打滑、被挡）；
4. 轨迹与路径错位 → ICP 跳变（H2）；
5. wz 恒值+轨迹静默 → Shim（H4）；
6. /odom 与 /Odometry 不一致 → odom_bridge（mount_rpy/高度）。
