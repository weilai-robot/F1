# 上肢静态方向测试

用于 `feat/amp-deploy` 的 X1 29DOF 真机，逐个检查腰 yaw/roll/pitch 和左右肩、肘、腕，共 **17 个上肢关节**。下肢 12 个关节沿用现场配置的静态 stand 目标，不做方向测试。准备姿态会从当前反馈用现有 2 秒 PD 插值到 stand；后续测试模式的下肢目标始终相同。

工具从 `build/` 中已经安装的配置生成独立测试配置，保留现场 DCU 网卡、执行器 ID、传动方向和标零偏移。控制仍由原 C++ PD 模块以 1000 Hz 执行，Python 只发送静态模式事件、观察反馈和记录结果。独立配置只加载 ControlModule、DcuDriverModule，不加载行走策略或手柄模块，Guide 不会触发 AMP。原 AMP 配置文件不被改写。

## 1. 更新并构建

先停止正在运行的普通控制进程，将机器人可靠支撑/吊装，确保静态测试过程中不会失去支撑。测试会使能执行器，启动脚本沿用原 `run.sh` 的颈部保持和 setcap 流程。

```bash
cd ~/Robot_github/F1
git pull --ff-only origin feat/amp-deploy
git submodule update --init --recursive
bash scripts/build.sh
```

构建会安装新的 `run.sh` 配置选择入口。保留并核对现场 DCU/标零配置；生成工具读取的是安装后的 `build/cfg/`，不能用默认配置代替现场标定。

## 2. 终端 A：启动独立静态控制

```bash
cd ~/Robot_github/F1
bash scripts/run_upper_direction_test.sh start
```

默认测试增量 **0.10 rad（5.73°）**；需要增大时，先停止本次测试控制，再重新启动：

```bash
bash scripts/run_upper_direction_test.sh start --angle 0.15
```

允许 `(0,0.20]` rad，所有目标会逐项核对现场关节限位，超限即拒绝生成配置。肩 roll 的零位在上限，工具自动使用 **−angle**；其他关节使用 **+angle**。目标为 `现场 stand 默认角 + 测试增量`，不是修改标零偏移。

启动时先保持 idle，尚未进入 stand。脚本发现已有 `aimrt_main` 会拒绝另起一个，避免两个控制进程争用总线和关节命令。

## 3. 终端 B：逐关节测试

```bash
cd ~/Robot_github/F1
bash scripts/run_upper_direction_test.sh test
```

程序会加载 ROS2 和生成的消息类型环境，检查 `/joint_cmd`、`/joint_states`、`/actuator_cmd`、`/actuator_states` 和独立静态模式入口。现场 DCU 的 `enable_actuator` 和 `actuator_debug` 必须为 true；生成时会检查上半身电机是否位于已启用的 DCU、是否遗漏或出现重复 CAN 地址。需要与 ROS2 相容的 Python、rclpy、my_ros2_proto 和 python3-yaml；不需要训练仓库、ONNX 推理或 MuJoCo Python 包。

操作流程：

1. 第一次回车：进入静态 stand 基准，等机器人姿态稳定。
2. 程序显示一个关节、测试增量、电机绑定和模型预期方向。回车开始该关节；`s` 跳过；`q` 结束。
3. 目标经过 2 秒插值后保持。工具确认关节和电机侧的目标、kp/kd 均到达，再打印反馈位移。观察实际动作，输入 `s` 方向一致、`r` 方向相反、`n` 完全不动、`u` 不明显、`w` 动了其他关节，或 `q` 结束。
4. 该关节目标自动恢复基准位，下一次回车才开始下一个关节。程序不会自行改变任何电机方向。

只测试指定关节，例如右肩 pitch：

```bash
bash scripts/run_upper_direction_test.sh test --joint right_shoulder_pitch_joint
```

可以重复 `--joint` 选多个上肢关节，下肢关节不能选择。查看全部顺序和模型方向：

```bash
bash scripts/run_upper_direction_test.sh list
```

右臂不动时，先保持默认 0.10 rad 测试角，单测右肩 pitch。工具显示 DCU/channel/CAN ID 和关节、电机位移。它只确认指令到达**主机电机缓存**，不把缓存变化当成电机已经收到 CAN 指令。

终端 A 已启动时，可在另一终端执行只读诊断（不发送任何模式或关节指令）：

```bash
bash scripts/run_upper_direction_test.sh diagnose
```

默认观察 2 秒，输出腰与左右臂全部 17 个关节的目标、反馈、kp/kd、电机映射误差及观察期位移，并写 `build/test_logs/data_csv/upper_link_diagnose_时间戳.json`。若没有正在进行的动作，位移为零是正常静止，不能仅据此判定故障。测试某关节并保持目标时，可同时执行诊断查看该目标的跟踪误差。

当前配置中右臂共用 `body / channel_2 / CAN 1～7`，左臂共用 `body / channel_1`；腰 roll/pitch 在 `body / channel_3`，腰 yaw 在 `hip / channel_3`。现场使用其他网络配置时，显示的是安装配置中的实际路由。详细排查依据见 [上半身测试链路审计](upper_direction_link_audit.zh_CN.md)。

模型坐标为 X 前、Y 左、Z 上。“左/右”均指机器人自身。中立垂臂时，肩 pitch 正角度向后摆、肘 pitch 正角度向前折，肩 roll 的负测试角向外展开。腰 pitch 正角度前折，腰 roll 正角度向左折，腰 yaw 正角度向左转。

肩/肘 yaw 与腕部旋转容易受观察视角影响。程序从部署 MJCF 的父子零位旋转计算每个关节在基准姿态的**正角度旋转轴**；按右手定则比较，勿只按 pitch/roll/yaw 名称猜方向。直臂的轴向旋转位移可能不明显，可在对应部位贴标记观察，选择 `u` 保留待查；不要把“不明显”记录成“方向相反”。腕部 L28 的 kp/kd 不决定其内部位置控制行为，工具保留原静态增益，不据此自动加大力度。

## 4. 结果和退出

结果保存到：

```text
build/test_logs/data_csv/upper_direction_时间戳.csv
build/test_logs/data_csv/upper_direction_时间戳.json
```

CSV 以 25 Hz 记录阶段、被测关节、全部 29 个关节的目标/反馈/kp/kd，以及 17 个上半身电机的目标/反馈/kp/kd。关节位置已减去标零偏移，电机位置为原生电机坐标。JSON 记录现场输入的 `same/opposite/no_motion/unclear/wrong_joint`、路由、反馈均值、跟踪误差和测试前后位移。反馈位移小于测试增量的 20% 会记录 `motion_status=no_motion`，这是排查提示，不自动修改 direction。数值跟踪良好本身不能证明机械方向；机械结论来自现场观察。

正常结束保持静态 stand 基准目标，再在终端 A 按 Ctrl+C 关闭测试控制。终端 B 的 Ctrl+C 或异常中止会尝试切到当前反馈姿态 keep；反馈超过 0.5 秒未更新时尝试切到零增益 idle。软件退出不是硬件急停，异常动作由现场立即停止。

恢复普通 AMP 操作：结束终端 A 的测试进程后，再执行 `cd build && bash run.sh`，使用原 B → A → Guide 流程。

## 5. 只生成/预览与本地验证

服务器只预览，不启动、不发送模式事件：

```bash
bash scripts/run_upper_direction_test.sh prepare --dry-run
```

生成文件为 `build/cfg/x1_cfg_upper_direction_test.yaml`、`build/cfg/control_module/upper_direction_test.yaml` 和同目录 JSON 清单。当前清单版本为 2；升级脚本后必须停止旧测试，再运行 `start` 重新生成并启动。配置采用 yaml-cpp 可读取的 JSON/YAML 格式；源文件不改写，测试前会核对配置哈希，修改后需重新生成并重启。可用 `AIMRT_DIR` 指定其他已安装目录。

离线检查，无需 ROS2 或硬件：

```bash
python3 -m unittest discover -s scripts/tests -p 'test_upper*.py' -v
```

15 项离线测试通过：包含全部 17 个模式的目标及电机边界检查、下肢保持、名称/偏移换算、错误映射/零增益中止、右臂有指令但无位移的记录、只读诊断无发布，以及旧有的返回基准和断流中止。C++ 测试读取当前真实部署配置，编译实际 DCU/PowerFlow SDK，验证 17 个电机的 CAN 缓冲槽、位置/增益编码和反馈槽隔离；UBSan 检查通过。C++ 编译器和 PyYAML（或 Ruby YAML）缺失时该项会跳过。尚未在真机或完整 Linux AimRT/ROS2 环境执行本次修改，离线测试不验证总线接线、固件或物理方向。
